# Fit Nova 1.5: redesign, sleep & alarms, routines

The owner asked for a big overhaul ("serious work", "modern + simple minimal", "good colors", "open source illustrations icons", "all good features full performative") and was not available to answer questions, so every decision below was made on their behalf. The research behind it is in `D:\CodeFILES\FitNova-assets\research\*.md`:

| File | Contents |
|---|---|
| `design.md` | palette options, contrast report, type scale, component rules, signature, motion |
| `perf.md` | low-end performance audit with file:line findings, baseline profile, camera tuning |
| `ux.md` | per-screen bugs, issues and improvements, plus ranked feature ideas |
| `alarm.md` | alarm-challenge, sleep-log and reminder blueprint (manifest, permissions, ringing, adb tests) |
| `icons.md`, `emoji.md`, `illustrations.md` | asset sources, licences, conversion notes |

## 1. What ships in 1.5

1. **New visual system:**
   - the "Nova Indigo" palette, in light and dark
   - Manrope font
   - Phosphor icons
   - Fluent Emoji Flat artwork
   - Open Doodles and GitLab illustrations
   - refreshed components and charts
2. **Navigation:**
   - tabs are **Home · Train · Food · Sleep · Ranks**
   - Profile becomes a full-screen page, opened from an avatar button in every tab header
   - History is a full-screen page
   - onboarding runs on first launch
3. **Sleep & alarms (M3):**
   - wake-up alarms that you dismiss by doing reps on camera, with a maths fallback and limited snooze
   - a sleep log filled by "Going to bed" plus the alarm
   - a daily workout reminder
4. **Guided routines:** built-in multi-exercise circuits with rest timers. Each step is saved as a normal workout.
5. **Voice coach:** TextToSpeech counts reps and speaks posture cues. On by default, with a toggle.
6. **History:** month heatmap, day list with delete, and personal bests.
7. **Fixes:** the bugs from `ux.md` and the performance findings from `perf.md`.
8. **Release:** version 1.5 (versionCode 15), README with screenshots, GitHub release.

## 2. Architecture rules (every agent)

- **Stack:**
  - Compose Material3 with plain state
  - the single `AppViewModel` plus `Graph` singletons
  - plain SQLite via `Db`
  - hard-coded English strings
  - no new third-party libraries; `androidx.profileinstaller` is the only addition
- **Low-end first:**
  - no blur, shadow, elevation, gradients on chrome, Lottie or infinite animations (the ringing alarm screen and the camera "searching" pulse are the only exceptions)
  - animate only in the draw or layer phase (`graphicsLayer {}`, Canvas reading state inside the draw lambda) with short tweens (120–300 ms)
  - use `LazyColumn`/`LazyRow` with `key` and `contentType` for anything long or repeated
  - draw blocks allocate nothing per frame
  - keep heavy work off the main thread
- **Flat look:**
  - depth comes from tone, not shadows
  - cards are `surfaceContainer` with a 1 dp `outlineVariant` hairline
  - one primary button per screen
  - number-first cards: label, then one big tabular number, then a small unit
- **Accessibility:**
  - every icon-only control gets a `contentDescription`
  - touch targets are at least 48 dp
  - status is never shown by colour alone (add an icon or word)
- **Workout mode is always dark:** Session, Rest, Summary and the alarm Ring screen force `FitNovaTheme(dark = true)`.
- **Text:**
  - minimal: a title plus at most one short supporting line
  - icons, emoji artwork and illustrations do the rest
  - no paragraphs

## 3. Design system (owned by foundation-ui; `design.md` has the details)

### Colour

Use the `recommendedTokens` block in `design.md` exactly:
- `lightColorScheme`/`darkColorScheme` (indigo brand `#534EF5` light / `#7E8BFF` dark)
- `NovaColors` with good/warn/bad, points/minutes/water/sleep, protein/carbs/fat, upper/lower/core/cardio and track
- `LocalNova`, plus `Nova.colors` for composables
- `Nova.Live*` colours for the camera overlay, and `Nova.Gold/Silver/Bronze`
- `LocalDark` (Boolean) so components can choose the light or dark illustration variant

The colour language is fixed and used the same way everywhere:

| Role | Colour |
|---|---|
| points | indigo |
| minutes | coral |
| water | cyan |
| sleep | violet |
| protein | raspberry |
| carbs | gold |
| fat | violet |
| 💪 Upper | violet |
| 🦵 Lower | gold |
| 🧘 Core | cyan |
| 🏃 Cardio | raspberry |

Rules:
- Data colours are for marks, dots and 14 % tints, never for text.
- Status colours: text-grade `good/warn/bad` inks.

### Type

- One family, **Manrope** (variable TTF at `res/font/manrope.ttf`), in weights 500/600/700/800.
- Use the type scale in `design.md`: displayLarge 96, displayMedium 64, displaySmall 48, headlineLarge 36, headlineMedium 30, headlineSmall 24, titleLarge 20, titleMedium 17, titleSmall 15, bodyLarge 16, bodyMedium 15, bodySmall 13, labelLarge 15, labelMedium 13, labelSmall 12.
- Numeric roles turn on `tnum`.
- No text below 12 sp.

### Shapes and spacing

- Radii: extraSmall 8, small 12, medium 16, large 24 (cards), extraLarge 32 (sheets, dialogs). Buttons, chips and the segmented control are pill shaped.
- Spacing is a 4 dp grid:
  - screen gutter 16 dp (20 dp at 400 dp width and up)
  - card padding 16 dp (hero 20 dp)
  - 12 dp between cards, 24 dp before a section title

### Signature

- **Nova dot:**
  - the active-tab marker
  - the cap riding the head of every progress arc
  - today's marker under the week bars
  - the live rep blink
- **Open arc gauges (270°, gap at the bottom) instead of closed rings.** The Today card has three concentric arcs (points, minutes, water).
- **Number-first bento cards on Home.**
- **Workout mode is always dark.**
- **Duotone icons** (`ic_*_duo`) on 14 % role-tint tiles for semantic icons.
- **Fluent emoji artwork** on soft tonal tiles for badges, categories, food and empty states.

### Motion

See `design.md`:
- springs and tweens only for alpha, translation, scale and Canvas progress
- tabs swap instantly with a 120 ms fade-in (no Crossfade)
- overlay screens enter with a fade plus a 12 dp slide over 200 ms
- respect the system animator scale

## 5. Shared components (foundation-ui, `ui/Components.kt` and `ui/Charts.kt`)

Existing names keep working: new parameters get defaults and old signatures still compile. The new or changed API:

- **Cards:**
  - `Panel(modifier, onClick?, padding, content)` is flat: `background(shape)` plus a border. It is not a Material `Surface`.
  - `HeroPanel` uses 20 dp padding.
- **Headers:**
  - `ScreenHeader(title, subtitle?, trailing)` is the tab header row. Its `trailing` slot usually holds `ProfileButton(name, onClick)`, a 40 dp avatar with a 48 dp touch target and contentDescription "Profile".
  - `TopBar(title, onBack, actions)` is for full-screen pages (Profile, History).
- **Section titles:** `SectionTitle(text, emoji: Int? = null, action: String? = null, onAction)`. The action renders as a real button only when `onAction` is set; otherwise it is a plain trailing label.
- **Tiles:**
  - `IconTile(icon: Int, tint: Color, size = 40.dp)`: a duotone icon on a tint at 14 %.
  - `EmojiTile(emoji: Int, tint: Color? = null, size = 44.dp)`: Fluent artwork on a tonal tile.
  - `Emoji(res, size)`: the artwork alone.
- **Illustrations:** `Illustration(illu: Illu, modifier, height)` plus `enum class Illu(light, dark)` for the 14 scenes.
- **Empty states:** `EmptyState(title, body? = null, illu: Illu? = null, emoji: Int? = null, action: String? = null, onAction)`. `EmptyNote` stays as a thin wrapper.
- **List rows:** `ListRow(title, subtitle?, leading: (@Composable () -> Unit)?, trailing: (@Composable () -> Unit)?, onClick?)` with a minimum height of 64 dp.
- **Buttons:**
  - `PrimaryButton`: a pill, 56 dp tall.
  - `SecondaryButton`: a tonal pill, 56 dp, no border. The `color` parameter is kept.
  - `IconCircleButton(icon, contentDescription, onClick, container = surfaceVariant, tint)`: 48 dp.
- **Chips and tags:**
  - `Chip(text, selected, onClick, emoji: Int? = null)`: selected = `inverseSurface` fill.
  - `Tag(text, tone, dot = false)`: a role tint at 14 % with onSurface text. For status tags, the text uses the status ink.
- **Other controls:**
  - `Segmented`: a pill track with a thumb that slides in the layer phase.
  - `Pill`.
  - `StatTile(label, value, unit?, emoji: Int? = null)`.
  - `Avatar(name, size, tint, ring)`: the initial on a 16 % tint.
- **Sheets and dialogs:**
  - `NovaSheet(onDismiss, footer: (@Composable () -> Unit)?, content)`: a `ModalBottomSheet` styled to spec (surfaceContainerLow, extraLarge top, drag handle, 20 dp padding, nav-bar inset, pinned footer). It also has its own `SnackbarHost`-free message line support: an optional `message: String?` parameter.
  - `ConfirmDialog(title, text?, confirm, destructive, onConfirm, onDismiss)`.
- **Settings and inputs:**
  - `ToggleRow(icon, title, subtitle?, checked, onCheckedChange)`: the whole row is `toggleable` with role Switch.
  - `NavRow(icon, title, value?, onClick)`: a settings row with a chevron.
  - `Stepper(value, onChange, step, range, unit)`: a value between two 48 dp − and + buttons with labels.
- **Charts** (no per-frame allocations, animation read in the draw phase):
  - `Arcs(values: List<Pair<Float, Color>>, size, stroke, gap, content)`: concentric 270° open arcs with the Nova dot cap.
  - `Arc(progress, color, …)`: a single open arc.
  - `WeekBars(...)`: the bar-grow animation actually runs, the goal bar is green, and today has a Nova dot.
  - `LineChart(...)`: nulls are gaps and are never bridged.
  - `MacroDonut(...)` uses the Nova macro colours.
  - `Meter(...)`: the fill is animated in the draw phase.
  - `Rings` and `Ring` stay as wrappers that draw open arcs.
- **Photos:** `AssetPhoto` and `PhotoCard` take the perf fixes from `perf.md`: alpha in a `graphicsLayer`, decode sized by width and height, no title read twice.

## 6. Platform foundation (foundation-platform)

- **Navigation in `AppViewModel`:**
  - `enum class Tab { HOME, TRAIN, FOOD, SLEEP, RANKS }`
  - `enum class Screen { PROFILE, HISTORY }`, with `var screen: Screen?`, `openProfile()`, `openHistory(day: LocalDate? = null)` and `closeScreen()`
  - `historyDay: LocalDate?`
- **Onboarding:**
  - `var onboarded` defaults to true when `daily_goal`, `body` or a session already exist (people upgrading from 1.4)
  - `fun finishOnboarding(goal: Int?)`
- **Settings:**
  - `voice: Boolean` (default true) with `changeVoice(Boolean)`
  - `reminder: Int?` (minute of day; null means off) with `changeReminder(Int?)`. This stores the pref and calls `app.fitnova.alarm.Reminders.schedule(context, minute)`. foundation-platform writes `Reminders` as a no-op stub; the sleep agent implements it.
  - `sleepGoal: Int` (minutes, default 480) with `changeSleepGoal(Int)`
- **Today ticker:** `today: StateFlow<LocalDate>` refreshes on resume and at midnight. `stats` and `badges` combine workouts with today, so nothing goes stale after midnight. Water also uses the current day.
- **Delete:**
  - `deleteWorkout(w)`: if the workout is synced, call `Api.deleteWorkout(id)` (PostgREST `DELETE /rest/v1/fn_workouts?id=eq.<id>`; RLS "own rows" already allows it) and only delete locally after the server confirms. If the server call fails, post the message "Can't delete while offline". Unsynced workouts are deleted locally at once.
  - Add the matching `WorkoutStore.delete(id)`.
- **Sleep and alarm data:**
  - `Db` version 3 adds the `sleep` and `alarms` tables. The upgrade is additive.
  - `domain/Sleep.kt`:
    - `SleepEntry(id, bedAt, wakeAt, source: "tap"|"alarm"|"manual")` with `minutes`
    - `SleepStats(lastNight: SleepEntry?, week: List<Pair<LocalDate, Int>>, avgMinutes, avgBedMinuteOfDay, consistency, debtMinutes)`
    - `sleepStats(entries, goal, today, zone)` (a basic, correct implementation)
  - `domain/Alarm.kt`:
    - `Alarm(id, hour, minute, days: Int /*bit0 = Monday … bit6 = Sunday, 0 = one-time*/, enabled, exercise: Exercise, reps, label)`
    - `fun Alarm.next(after: ZonedDateTime): ZonedDateTime?`
  - `data/SleepStore.kt`:
    - `SleepStore` with `entries: StateFlow<List<SleepEntry>>`, `load()`, `save()`, `delete()`, plus `bedtime: StateFlow<Long?>` with `goToBed()`, `wakeUp(source)` (creates the entry) and `cancelBed()`
    - `AlarmStore` with `items: StateFlow<List<Alarm>>`, `load()`, `save()`, `delete()`
  - Both are wired into `Graph` and loaded in the ViewModel's init.
  - **These public names are frozen for phase 2. Agents may add to them but may not rename them.**
- **Stub screens** compile and are clearly marked TODO for their phase-2 owner:
  - `ui/SleepScreen.kt` with `SleepScreen(vm, padding)`
  - `ui/HistoryScreen.kt` with `HistoryScreen(vm)`
  - `ui/OnboardingScreen.kt` with `OnboardingScreen(vm)`
- **AppRoot:**
  - render the Sleep tab
  - Profile and History as overlays when `vm.screen` is set, with back closing them
  - onboarding when `!vm.onboarded`
  - `ProfileScreen(vm)` now takes no padding and has a back arrow
- **Robustness:**
  - `Sync.run()` runs entirely on `Dispatchers.IO` and catches every exception (non-API errors become `Failed`)
  - every `Api` call, including Keystore token work, runs on IO
  - ViewModel catch blocks catch `Exception`
  - an expired session (refresh failure) clears `vm.username`
  - stats and badges are computed once per emission
  - init loads workouts first and shows a "loading" state instead of empty-state flashes: `var loaded`
- **Camera (`pose/PoseCamera.kt` internals):**
  - set the initial camera selector before binding, so the camera isn't opened twice
  - check `hasCamera` and fall back to the other camera
  - run the analyzer on a background executor and post results to the main thread
  - pose detector on CPU only
  - low-RAM devices (`ActivityManager.isLowRamDevice` or less than 3 GB) use 480×360 analysis
  - the train agent later restyles only the overlay drawing
- **Build:**
  - versionCode 15, versionName "1.5"
  - add `androidx.profileinstaller:profileinstaller:1.4.1` and `app/src/main/baseline-prof.txt` (rules from `perf.md`)
  - window background follows the in-app theme in `MainActivity` before `setContent`, so there is no white flash
  - `res/values` bg `#F5F6F8`, `values-night` bg `#0B0C0F`
- **Tests:** keep the existing 28 passing, and add tests for `sleepStats` (crossing midnight) and `Alarm.next` (repeat days, one-time, DST).

## 8. Verification

Each phase-2 agent runs `gradlew.bat testDebugUnitTest assembleDebug` in its worktree until it is green, then commits on its branch. Only the sleep agent may use the emulator (headless) to test alarms, and it shuts the emulator down afterwards.

After the merge, the orchestrator:
- runs a full build and the tests
- runs an adversarial multi-lens review and fixes what it confirms
- takes emulator screenshots of every screen in light and dark
- tests alarms over adb
- builds the release (R8)
- writes the README, makes the dated commits, pushes, and publishes the GitHub release v1.5
